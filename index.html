retrieval-augmented generation

Why AI makes things up —
and how RAG quietly fixes it.

A language model answers from memory, so it sounds right even when it's wrong. RAG lets it look things up first. Here's that idea told three ways: a talk, a slow-motion walkthrough of the machinery, and a lab you can type your own questions into.

Everything below runs in your browser. No install, no sign-up, no API key, and no network once the page has loaded.

The lab rag-lab.html

Nine tabs, left to right — that order is the pipeline. Watch keyword search score zero on a question the document plainly answers, see a reranker refuse to answer at all, and break the whole thing yourself. Type your own questions; every number on screen is computed in the page as you watch.

Both open on GitHub so they render as pages rather than raw text — the only links here that need a connection. Everything above works offline. The deck's own script isn't a file: press S on any slide and it appears beside it, sources and all.

About the numbers. The lab doesn't call an embedding model — it uses a hand-built concept map, which is what lets the whole thing run offline in a single file with no dependencies. The behaviours are real and reproduce with real embeddings: vocabulary mismatch, blindness to identifiers, chunks losing their context, the recall/precision tradeoff. The specific scores are illustrative. Likewise, the generation tab replays recorded output — a browser can't reach a model API directly, and shipping a key inside a page anyone can open would be the wrong thing to do.

Taking it somewhere without wifi? Download the repo as a ZIP, unzip it, and open index.html. That's the whole setup. Web fonts will silently fall back to system faces — it looks a little different and lays out identically. Nothing else on these pages touches the network.
